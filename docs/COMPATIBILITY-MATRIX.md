# DOM Compatibility Matrix

This matrix records the exact detector and mapping behavior covered by the offline compatibility corpus. Each fixture uses neutral text, synthetic identifiers, fixed viewport geometry, and no authentication state. External-looking media URLs use the reserved `example.test` host and are inspected as URL metadata only.

`generic-path` means the fixture exercises the shared DOM model. `site-specialized-path` names the currently exercised site branch. These labels describe this corpus; they do not claim support for every page on a platform.

The first two Pintia fixtures are sanitized from the repository's existing Pintia-style regression structures. Their original task text, long numeric IDs, and page-specific data have been replaced. The extension's current Pintia branch requires a numeric question-list ID, so the list fixture uses clearly synthetic eight-digit identifiers solely to exercise that selector.

Closed shadow root: Page-owned closed roots are not exposed to extension DOM traversal. Cross-origin iframe DOM: Cross-origin frame document access is denied by browser origin policy.

The corpus is executed by `src/content/detector/compatibilityCorpus.test.ts`. Contract and fixture data live in `src/content/detector/testFixtures/compatibilityFixtures.ts`. Known limitations are recorded as expected outcomes; they are not counted as ordinary detector failures. A future compatibility fix must add or update a deterministic fixture before changing the production detector.
